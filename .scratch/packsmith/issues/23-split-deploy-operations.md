# 23: 部署操作拆分——上传 / 停止 / 启动 / 重启

**What to build:** 部署不再是单一动作。部署对话框在确认上传计划时可选**操作**：
- **仅上传**：只按映射行传文件，不执行任何命令组
- **仅停止**：只执行停止命令组（不传文件）
- **仅启动**：只执行启动命令组（不传文件）
- **重启（默认）**：先停止再启动；停止失败即中止并展示错误（既有语义不回退）；是否先传文件由"仅上传"语义并入——重启 = 上传 + 停 + 启，与现状一致

各操作逐目标执行，进度/输出快照/取消等既有展示与控制不回退；部署历史记录本次操作类型（旧记录默认"重启"）；构建成功后的自动连锁仍为完整"上传 + 重启"，不变。中文 i18n。

**语义细节：**
- 操作是**对话框级**选择（对本次勾选的所有目标统一生效），不做逐目标混合操作
- 仅停止/仅启动时上传计划区只读展示（不参与本次操作）；仅上传时不执行停止/启动
- 停止/启动的输出快照与失败展示复用既有阶段 UI

**Blocked by:** None（基于集成 tip；需等部署"等待"诊断修复落库后再开工，同文件避免冲突）

**Status:** resolved

> 实现：引擎新增 `DeployOperation`（restart/upload/stop/start）驱动 `run_deploy` 按操作裁剪阶段（重启 = 上传+停止+启动不变；仅停止失败不设 `stop_failed`、不出现"中止重启"恢复入口），`start_deploy` payload 增 `operation` 且上传校验（构建成功/产物目录/行归属/`no_files_selected`）仅对上传类操作生效，取消与事件信封不变、自动连锁仍为完整重启；`deploy_records` 增 `operation` 列（v14 迁移，旧记录由列默认值读作 restart）随每次部署落库；前端对话框级操作选择器（默认重启），仅停止/仅启动时上传计划区只读、payload 只带目标（`files: []`）且无需可上传行即可发起，中文 i18n，GLOSSARY 增"部署操作"词条。
