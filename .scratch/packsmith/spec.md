# Spec: Packsmith v1

Status: ready-for-agent
Date: 2026-11-02
Source: /grill-with-docs 设计树共识（术语见根目录 `GLOSSARY.md`）

## 一句话

Tauri 桌面打包应用：从 git 获取项目 → 临时工作区 mvnd 打包 → 构件入库 → 上传服务器 → 命令组重启服务。v1 仅 Java/Maven。

## 技术栈

- **框架**: Tauri（Rust 后端 + WebView 前端）
- **前端**: React + TypeScript + Vite + Tailwind + shadcn-ui
- **i18n**: 框架预留，v1 仅中文
- **托盘**: 系统托盘进 v1（见设置页）
- **持久化**: 单库 SQLCipher（rusqlite）加密，密钥自动生成、存应用数据目录密钥文件 `db.key`（0600），**不使用系统钥匙串**（ADR-0003，取代 0002 的密钥存放方式；整库加密与"只拷 db 不可读"不变）；项目、服务器、部署目标、凭据全部入该库（ADR-0002）
- **SSH**: Rust 侧 russh + russh-sftp，进程内实现
- **打包任务**: Tauri command + 后台任务，前端经事件获取进度

## 页面（4 个）

### 首页
总览 + 快捷入口，无独有功能：
- 最近打包记录列表（项目 / 分支 / 时间 / 结果）
- 快速发起打包入口
- 服务器概览卡片（连接状态、最近部署时间）

### 项目管理
- 项目类型下拉框：v1 仅 Maven（Java）可选，Gradle 等以 disabled 项预留
- 获取方式两种：
  - **新建**: 填 git URL，clone 到用户指定的 workspace 根目录（默认 `~/Packsmith/workspace`）
  - **导入**: 注册已有本地路径
- v1 不做 pull / 分支管理 / 远程刷新（界面预留刷新按钮）

### 服务器管理
- 服务器 CRUD：主机、端口、用户、凭据（私钥路径 + passphrase，或密码）
- 保存时提供**连接测试**（必有的按钮）
- 服务器只管连接；"放到哪、怎么重启"属于部署目标

### 设置
- 应用版本信息（tauri 版本）
- **Git 账号**：用户名 + 密码/访问令牌，入加密库；clone 与分支拉取在远程要求认证时自动使用（v1.1 仅 HTTPS 认证，SSH 协议 URL 明确提示）
- **mvnd settings.xml**：全局一份（v1.2）——设置页多行编辑器写入 `<appdata>/mvnd-settings.xml`，构建自动追加 `-s`（私服依赖场景）
- 托管工具链区（git / JDK / mvnd）：三态展示——已检测（PATH 上有，仅展示）/ 已托管 / 缺失；一键下载到 `<appdata>/tools/`。**执行只用托管工具链**，PATH 不作为执行来源（ADR-0001）
- **依赖仓库**：`<appdata>/m2-repo`，mvnd 构建统一使用，与用户 `~/.m2` 隔离（ADR-0001）；**持久保留、从不删除**，构建间复用依赖缓存
- **关闭窗口行为选项**：最小化到托盘 / 退出应用（默认最小化到托盘；托盘菜单始终保留"退出应用"）
- 托盘：打开主界面 / 退出；构建进行中给状态提示

## 核心流程：打包 → 部署

### 打包（Build）
1. 打包面板实时 `git ls-remote` 拉取分支列表，下拉选择（记住上次选择）
2. 自动创建**临时工作区**，clone 指定分支
3. 执行**构建命令**——随项目可编辑，默认 `mvnd package -DskipTests`；执行环境完全自包含（见 ADR-0001）：mvnd/git 用托管工具链，`-Dmaven.repo.local=<appdata>/m2-repo` 指向**依赖仓库**，与本地 `~/.m2` 零冲突
4. 产物扫描 `target/`：单个 jar/war 自动选中；多个时用户勾选，选择结果记为该项目默认
5. 成功 → 构件复制进**产物库** `<appdata>/artifacts/<项目>/<构建时间>/`，保留最近 N 次 + 手动清理；失败 → 只留构建日志
6. 临时工作区成功失败都删除；构建日志可查看
7. 构建进行中：托盘状态提示

### 部署（手动触发）
1. 构建完成页给"部署"按钮，可勾选多个**部署目标**
2. 上传：部署目标持有**文件名→目录映射表**（编辑目标时配置，多行）；部署时按行自动匹配本次构建产物并 SFTP 以原文件名覆盖到对应目录，产物缺失的行标红跳过；部署对话框变为确认解析后的上传计划（行可勾选，空文件名行内联补选）；不做全量上传
3. 每个部署目标有"构建成功后自动连锁部署"开关，**默认关**

## 领域模型

- **项目 (Project)**: git 来源或本地路径；类型、构建命令、默认产物选择
- **服务器 (Server)**: SSH 连接信息 + 凭据
- **部署目标 (Deployment Target)** = 项目 × 服务器：
  - 文件名→上传目录映射表（v1.2 取代单一上传目录）
  - **启动命令组 / 停止命令组**：各为 N 条命令，多行（如 `cd /home/app \n sh start.sh start`），作为一个整体按序串行执行（`sh -c`），以 SSH 登录用户身份执行
- **重启 (Restart)**: 停止命令组 → 成功 → 启动命令组；**停止失败则中止重启、展示错误输出，由用户判断**（可手动单独执行启动命令组）

## 明确不做（v1）

- Gradle / 其他语言类型（仅预留占位）
- git pull / 分支管理
- 多 JDK 版本管理（托管各工具仅一个版本，**JDK 默认 1.8**；执行仅用托管工具链，PATH 仅检测展示——ADR-0001）
- 交互式 sudo / 终端模拟
- 实时日志流（v1 只有输出快照）
- systemd 托管
- 多语言（仅保留 i18n 框架）
- 托盘内直接发起打包

## 验收要点

- [ ] 全新机器（无 git/java/mvnd）可通过设置页下载托管工具链后完成一次完整打包
- [ ] 用户本地 `~/.m2` 在 Packsmith 打包前后内容不变（依赖仓库隔离生效，ADR-0001）
- [ ] clone → 选分支 → 打包 → 构件入库 → 上传 → 命令组重启 全流程走通
- [ ] 停止命令组失败时：不执行启动，错误输出可见，可手动执行启动
- [ ] 数据库文件被拷走后无法读出凭据（SQLCipher 生效，ADR-0002）
- [ ] 打包失败后临时工作区无残留
- [ ] 关窗行为随设置页选项生效
