# Packsmith 完全自包含：工具链与依赖仓库三重隔离

用户要求 Packsmith 是一个独立项目，不与本地环境的依赖产生冲突。因此做三重隔离：①执行只用托管工具链（`<appdata>/tools/`），PATH 上的工具仅用于设置页"已检测/缺失"的状态展示，绝不作为执行来源；②mvnd 构建统一加 `-Dmaven.repo.local=<appdata>/m2-repo`，依赖从 Packsmith 自己的仓库获取，与用户本地 `~/.m2` 完全隔离——该依赖仓库**持久保留、从不删除**，首次构建下载的依赖供此后所有构建复用，越用越快；③每次打包使用自动创建、打包结束即删的临时工作区，不在 Packsmith 之外留下任何状态。

这是真实取舍：首次构建需重新下载全部依赖、占用双份磁盘，换取的是零冲突与可预期的构建环境。被否决的方案："优先托管、回退 PATH"（省磁盘，但会把本地环境的不确定性带进构建）与"复用 workspace + 共享 ~/.m2"（快，但正是用户要避免的冲突源）。
